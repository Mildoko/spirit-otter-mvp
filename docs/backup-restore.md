# 备份、恢复与数据清理

## 原则

备份只用于受控试验连续性，访问限研究负责人和运维人员。备份同样受 30 天期限约束，并加密存储；删除用户数据后，下一轮备份轮换必须移除对应旧副本，不能承诺即时删除模型供应商日志。

## 备份

1. 在测试开始前记录应用版本、数据库迁移版本和配置项名称，不记录密钥值。
2. 使用 Postgres 管理工具生成加密备份，保存到不对局域网参与者开放的位置。
3. 记录备份时间、校验值、保留到期日和操作人。
4. 每次正式测试日前至少完成一次恢复演练。

## 恢复

1. 停止新会话进入并保留事故记录。
2. 建立隔离的空数据库，先应用同版本迁移，再恢复备份。
3. 验证匿名用户数、对话数、行动/回访外键和最新完成 turn。
4. 用测试邀请码验证登录、对话恢复和数据隔离。
5. 只有研究负责人批准后才切回服务；恢复后运行一次清理任务。

## 每日清理

在局域网主机的任务计划中每天运行 `npm run cleanup`。日志只保存各表删除数量和执行状态，不保存对话文本、证据片段或模型内部结果。

## 用户主动删除

`DELETE /api/me/data` 立即级联删除当前匿名用户的会话、消息、状态、行动、回访、安全和行为事件，并清除 Cookie。执行后用该会话访问 bootstrap 必须得到 401。
