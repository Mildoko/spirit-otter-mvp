# 内圈 ↔ 外圈切换 v0.1 版本计划

日期：2026-08-25

状态：`internal-prototype-implemented`，自动回归通过，等待多人盲化体验评审

工作名称：外圈「万象廊」

## 1. 版本结论

v0.1 只实现两个空间：

- **内圈｜私密船上世界**：用户与自己的 Agent 小队进行私密对话。
- **外圈｜万象廊**：浏览公开社区活动、公共主题和策划内容。

中圈、真人关系、群聊、发帖、评论、报名和站外通知全部推迟。首版只验证三件事：

1. 用户能否明确感知“私人世界”和“公共世界”的不同；
2. 用户能否自然进入外圈并随时返回；
3. 外圈内容能否被带回内圈，与飞儿或其他 Agent 私下讨论，而不泄漏内圈对话。

## 2. 参考图的产品语义

用户提供的效果图定义为外圈主视觉参考，而不是内圈背景。

| 图中元素 | 产品含义 | v0.1 用法 |
| --- | --- | --- |
| 发光的胶片式长廊 | 公共世界的内容入口 | 外圈主容器，每个大画幅对应一张公共内容卡 |
| 灯笼、锦鲤、莲花等画面 | 活动、主题和策划内容 | 作为活动封面或社区主题视觉，不表示用户情绪 |
| 船与用户 | 私人世界的边界仍然存在 | 外圈画面右下保留小船轮廓或“返回船上”锚点 |
| 鹿灵 | 陪同用户查看，不替用户行动 | 鹿禅不划船、不做社区运营；默认不在外圈主动说话 |
| 远方灯火与建筑 | 公共世界存在但不入侵 | 只提供环境层次，不展示虚构在线人数 |
| 星河与水面反光 | 内外圈共享的视觉宇宙 | 只承担氛围，不映射心理或任务状态 |

外圈画面应保留“东方夜湖、星河、半透明发光框架、金色反射”的气质。胶片孔洞可以保留为识别语言，但大画幅必须是可理解、可操作的内容窗口，不能只是自动播放的装饰轮播。

## 3. v0.1 用户流程

### 3.1 从内圈进入外圈

1. 用户在内圈看到常驻但克制的入口：`去外圈看看`。
2. 飞儿可在有公开内容时显示一枚信差提示，但不弹窗、不自动打开、不连续催促。
3. 用户首次点击后，展示一次简短边界说明：

   > 外圈是公开内容区。进入不会带出你的私密对话；当前版本只能浏览，不能报名、发帖或联系他人。

4. 用户选择 `进入外圈` 或 `先留在船上`。
5. 确认后进行 700–1000ms 的镜头推进：发光长廊从远景成为主画面，船退到右下边界。
6. 不播放划船动作，不把移动距离做成进度，不调用 Agent 生成回复。

首次说明确认只记录“已看过边界说明”，不代表同意画像、通知或任何外部动作。以后进入可直接切换；设置中应允许重新查看说明。

### 3.2 在外圈浏览

外圈首屏只显示 3 个大画幅，避免信息瀑布：

1. **正在发生**：近期公共活动；
2. **与你可能有关**：仅依据用户已确认的兴趣或用户手动选择的筛选条件；
3. **随便看看**：策划主题和多样性探索，不假装个性化。

每个画幅至少显示：

- 标题与内容类型；
- 时间、城市级地点、费用或参与条件；
- 来源与更新时间；
- `演示内容` 或 `真实目录` 状态；
- 最多两个可理解的推荐理由；
- 一个主动作：`查看详情`。

外圈详情页仍然只读。唯一延伸动作是：

- `带回船上问飞儿`；或
- `带回船上和当前 Agent 聊聊`。

这两个动作都会先返回内圈，只传递所选公共内容的 ID、标题、来源和用户明确选择的关注点，不传递其他浏览轨迹，也不自动保存长期兴趣。

### 3.3 返回内圈

- 外圈所有层级固定显示 `返回船上`。
- 返回不需要确认，不显示“确定离开吗”，不制造未读或错过压力。
- 详情页、加载失败页和空状态都能直接返回。
- 返回后恢复进入前的 Agent、对话位置、草稿和滚动状态。
- 外圈内容若被用户主动带回，只在内圈形成一张临时公共内容卡；是否记作兴趣由飞儿另行询问。

## 4. 页面与状态模型

```text
INNER_PRIVATE
  └─ user_open_outer
       ├─ first_time → OUTER_BOUNDARY_NOTICE
       └─ returning_user → OUTER_ENTERING

OUTER_BOUNDARY_NOTICE
  ├─ cancel → INNER_PRIVATE
  └─ confirm → OUTER_ENTERING

OUTER_ENTERING
  ├─ success → OUTER_GALLERY
  └─ load_failed → INNER_PRIVATE + honest_error

OUTER_GALLERY
  ├─ open_item → OUTER_DETAIL
  ├─ take_inside → INNER_PRIVATE + PUBLIC_ITEM_CONTEXT
  └─ return → OUTER_EXITING

OUTER_DETAIL
  ├─ take_inside → INNER_PRIVATE + PUBLIC_ITEM_CONTEXT
  └─ back → OUTER_GALLERY

OUTER_EXITING
  └─ INNER_PRIVATE

any_state + high/imminent → SAFETY_PLAIN
```

建议公开类型：

```ts
type WorldCircleV01 = "inner_private" | "outer_public";

type WorldViewV01 =
  | "inner"
  | "outer_boundary_notice"
  | "outer_entering"
  | "outer_gallery"
  | "outer_detail"
  | "outer_exiting";

interface PublicPortalItemV01 {
  id: string;
  contentType: "activity" | "topic" | "curated_story";
  title: string;
  coverAssetId: string;
  summary: string;
  timeLabel?: string;
  cityLabel?: string;
  priceLabel?: string;
  sourceName: string;
  sourceUrl?: string;
  updatedAt: string;
  dataStatus: "demo" | "live" | "stale";
  reasonCodes: string[];
}
```

`WorldViewV01` 只保存在当前浏览器会话，不写入角色记忆。刷新后的默认行为：若用户正在外圈详情页则回到外圈首屏；完整退出并重新进入产品时默认回内圈。

## 5. 视觉与动效规格

### 5.1 内圈

- 保持船、用户和 Agent 小队为视觉中心。
- 外圈长廊只在远景以低亮度轮廓存在，避免抢夺私密对话。
- 入口可以由飞儿信差、远方门廊或顶层导航触发，但只保留一个主要入口。

### 5.2 切换

- 采用镜头推近、焦点转移和光线渐强，不做船只位移动画。
- 普通动效 700–1000ms；`prefers-reduced-motion` 下改为不超过 180ms 的交叉淡入。
- 切换期间允许用户取消或立即返回，不能锁住页面超过动画本身。
- 切换失败保持在内圈，并显示“外圈暂时没有连接上”，不展示假数据冒充成功。

### 5.3 外圈

- 大画幅是空间主角，船缩为右下边界锚点。
- 桌面首屏同时看到 3 张画幅；移动端一次显示 1 张，左右滑动或按钮切换。
- 当前画幅边缘使用柔和金光；未选画幅降低亮度，不用高频闪烁。
- 画幅内部使用真实 DOM 内容层，确保文字、按钮、键盘和屏幕阅读器可访问；Canvas/Pixi 只负责背景和过渡。
- 不显示虚构头像墙、在线人数、点赞数或“大家都在参加”。

## 6. 数据与隐私边界

### 6.1 v0.1 数据源

首个开发版本使用本地审核过的演示目录，并在每张卡上明确标记 `演示内容`。真实社区 API 不属于本版本。

建议只读接口：

```text
GET /api/community/v0.1/public-feed
GET /api/community/v0.1/public-items/:id
```

不得提供 `POST /join`、`POST /signup`、`POST /message`、`POST /publish` 或同类接口。

### 6.2 请求边界

外圈请求不得携带：

- 内圈消息或摘要；
- 情绪、风险、疗愈或命理信息；
- Agent 记忆；
- 精确位置；
- 联系方式；
- 未确认的兴趣推测。

若提供“与你可能有关”，v0.1 优先采用用户当次手动筛选；如使用兴趣档案，只允许在本系统内用已确认字段排序，不能把画像发送给目录来源。

### 6.3 事件白名单

允许记录：

- `outer_entry_opened`
- `outer_boundary_confirmed`
- `outer_gallery_viewed`
- `outer_item_opened`
- `outer_item_taken_inside`
- `outer_returned_inner`
- `outer_load_failed`

事件只记录匿名会话 ID、公共内容 ID、演示/真实状态、入口和时间，不记录私密对话、兴趣原文或详情页面停留轨迹序列。

## 7. Agent 行为

### 飞儿

- 是外圈入口说明者和公共内容信使。
- 可以解释“为什么出现这张卡”和“当前能做什么”。
- 用户选择带回内圈后，才在内圈参与讨论。
- 不自动保存兴趣，不连续提醒，不说“我替你报名了”。

### 鹿禅

- 外圈默认安静陪同，不主动解释活动或发表禅意评论。
- 用户把内容带回并主动询问后，才从传统文化或人生观照角度回应。
- 不把命理或禅宗解释用于公开推荐排序。

### tata

- 外圈默认安静陪同。
- 用户带回内容后，可以帮助判断当下精力、社交负担和舒适度。
- 不把用户的情绪或脆弱状态带回外圈。

## 8. 开发任务

### W0｜契约与演示目录（0.5–1 人日）

- 增加世界状态和公共内容共享类型。
- 建立 6–9 条审核过的演示活动/主题数据。
- 实现只读 Demo/Full 同构接口及 `dataStatus`。

### W1｜内圈入口与状态保持（1 人日）

- 增加唯一的 `去外圈看看` 入口。
- 保存进入前的当前 Agent、对话、草稿与滚动位置。
- 完成首次边界说明和后续直接进入逻辑。

### W2｜外圈万象廊 UI（2 人日）

- 实现胶片门廊、3 个大画幅、详情页和移动端单画幅布局。
- DOM 承载内容与按钮，视觉引擎承载背景和过渡。
- 完成加载、空状态、失败和静态回退。

### W3｜切换动效与返回（1 人日）

- 实现镜头推近/拉回、船只边界锚点与降低动态版本。
- 不实现划船、自由航行或进度动画。
- 所有外圈层级提供即时返回。

### W4｜带回内圈讨论（1 人日）

- 只传公共内容最小结构化上下文。
- 返回原 Agent 或由用户明确选择飞儿。
- 临时卡不自动进入长期兴趣档案。

### W5｜隐私、安全与测试（1–1.5 人日）

- 拦截任何私密上下文字段进入外圈请求和事件。
- high/imminent 中断切换并进入 `safety_plain`。
- 完成键盘、读屏、移动端、低动态和失败恢复测试。

预计总量：6.5–7.5 人日，不含正式外圈美术拆层和真实社区 API。

## 9. 明确不做

- 中圈与真人熟人关系；
- 用户主页、头像墙和在线人数；
- 发帖、评论、点赞、私信和群聊；
- 报名、支付、联系组织者或加入群组；
- 站外通知和主动推送；
- 精确位置、通讯录或社交图谱；
- 基于内圈对话、情绪、命理或疗愈内容的推荐；
- Agent 划船、自由航行、任务里程或关系进度；
- 自动播放的无限内容流。

## 10. 自动验收

### 状态与功能

- 首次进入展示边界说明，取消后仍在内圈。
- 再次进入不重复打扰，但能从设置重新查看说明。
- 入口、画廊、详情、带回讨论和返回状态可确定性恢复。
- 外圈失败不会破坏内圈对话或草稿。
- 外圈所有内容均显示来源、更新时间和演示/真实状态。

### 隐私与安全硬门禁

- 外圈请求中内圈消息、记忆、情绪、风险、命理和联系方式字段出现率为 0。
- 未授权兴趣长期保存率为 0。
- v0.1 外部报名、联系、发布和加入调用率为 0。
- 演示内容冒充真实活动率为 0。
- high/imminent 继续外圈切换、推荐或沉浸的比例为 0。

### 可用性与视觉

- 桌面和移动端都能在 2 次操作内从外圈返回内圈。
- 键盘和屏幕阅读器可以进入、浏览详情并返回。
- 降低动态模式无明显位移和闪烁。
- 视觉人工检查确认：发光门廊是外圈主体，船是私人边界，不出现 Agent 划船。

## 11. 人工体验评审

必须人工判断：

- 用户是否理解外圈是公共内容区，但自己尚未发言或加入；
- 首次边界说明是否清楚而不过度恐吓；
- 飞儿的提示是否精明有分寸，而非催促；
- 返回船上是否自然、无损失感；
- 参考图的东方幻想气质是否保留，同时内容仍可读、可操作；
- “带回船上讨论”是否让人感到信息被带入私人世界，而不是私人世界被带了出去。

人工评审完成前，版本只能标记为内部原型，不能宣称外圈体验已验证。

## 12. 受影响体验不变量

- `EX-02`：首次跨圈说明低压力且可取消。
- `EX-03`：每张内容卡只有一个默认动作，查看不等于报名。
- `EX-04`：进入、退出和停止浏览由用户控制。
- `EX-05`：三个 Agent 在外圈仍保持各自职责，不混成导游角色。
- `EX-07`：高风险中断外圈沉浸和推荐。
- `EX-08`：不以热度、错过或群体压力强化使用。
- `EX-09`：演示目录、加载失败和未实现能力如实呈现。
- `EX-10`：内圈数据不跨圈，返回与退出始终清楚。

本计划不修改金标、冻结样本、阈值或 Judge。实现时需要新增外圈状态、隐私硬门禁和浏览器 E2E，不得用点击率替代人工圈层安全感评审。

## 13. 当前视觉实现检查点（v6）

- 万象廊改为正面、三格等宽的上方中景，整体尺寸收窄，避免压住私人船体。
- 船、用户、鹿禅、tata 与飞儿作为一个完整组合固定在屏幕水平中轴的下方前景，不新增角色或替换船型。
- 万象廊采用暖金正面光与水面反射；船体采用月金主光和薄荷金轮廓光，让两个层级都清楚可读。
- 外圈界面统一采用黑体类无衬线字族，可见正文最小字号为 `20px`；标题、活动名称和主操作按层级放大。
- 三个胶片窗口只保留活动定位、标题、时间和“看一眼”主操作；较长摘要与来源移入详情页，避免放大字号后越出画幅。
- 1900×951 与 1280×720 保留三格完整信息；844×390 横屏保留标题和主操作，详情点击后展开；竖屏继续进入横屏提示。

该检查点保持 `EX-03` 单一主操作、`EX-04` 用户主动切换、`EX-05` 角色连续性、`EX-08` 非压力表达、`EX-09` 能力诚实与 `EX-10` 清楚退出。视觉重心、光照舒适度与黑体字号层级仍需人工体验评审。
