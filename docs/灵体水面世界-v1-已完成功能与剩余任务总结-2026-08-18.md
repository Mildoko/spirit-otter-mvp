# 灵体水面世界 v1：已完成功能、测试与剩余任务总结

日期：2026-08-18  
当前阶段：Demo 可内部体验；Full 保持场景与声音特性默认关闭，待发布环境验收后灰度开启。  
总体结论：场景纵向切片、声音系统 v1、服务端指令契约和主要自动化测试均已完成。当前剩余工作主要是正式素材、多设备人工验收、外部模型环境验证和后续视觉精修，不再存在阻塞本地 Demo 的核心功能缺口。

## 1. 已完成的功能

### 1.1 灵体水面世界场景

- 使用项目原始概念图建立 1672×941 的完整水面世界构图。
- 已建立场景资源目录和资源注册方式，保留原图作为当前主视觉，并加入独立涟漪层。
- 使用 Pixi 实现场景渲染，支持桌面高质量档和移动低质量档。
- 首次进入显示完整场景，对话默认收起，避免聊天面板遮挡主构图。
- 水獭具有真实 DOM 交互入口，支持鼠标点击、触摸和键盘 Enter 激活。
- 点击水獭可播放靠近反馈并打开对话抽屉；抽屉可收起并再次恢复。
- 支持水面与星空两种视角切换，并保存当前视角状态。
- 对话发送和回复已接入 `listen`、`think`、`speak`、`invite`、`approach`、`withdraw`、`safety_still` 等场景动作。
- 服务端根据回复策略生成确定性的 `visualCue`，前端不依赖模型直接控制动画。
- elevated、high、imminent 风险场景优先进入静止、低装饰的安全表现。
- WebGL 初始化失败或上下文异常时可回退到静态场景，文字对话不受影响。
- 支持 reduced-motion，核心状态不依赖大幅镜头运动表达。
- 桌面和移动布局已适配；移动端对话抽屉、输入框和关闭按钮不会横向溢出。

### 1.2 Agent 语音

- 每条新产生的 Agent 回复在用户开启声音后自动朗读一次。
- 使用浏览器 `SpeechSynthesis` 作为首版临时语音来源，并封装为可替换的 `SpeechAdapter`。
- 优先选择 `zh-CN` 声线，其次其他中文声线，最后回退到系统默认声线。
- 支持异步 `voiceschanged`，处理浏览器延迟提供声线的情况。
- 澜泊的深潮、拾岸和安全直述使用同一系统音色，通过不同语速和音调区分：
  - 深潮：`rate=0.92`、`pitch=0.96`
  - 拾岸：`rate=1.00`、`pitch=1.00`
  - 安全直述：`rate=0.95`、`pitch=1.00`
- 新发送会立即取消上一条语音，任何时刻最多播放一条语音。
- 历史消息刷新后不会自动重播，但每条助手消息均提供手动重播按钮。
- 系统无可用语音或朗读失败时，只显示提示，不影响文字聊天和安全支持。
- 已建立 Agent 声线注册表和完整性校验；后续新增 Agent 不需要修改 `AudioDirector`。

### 1.3 BGM、音效与混音

- 已加入水面和星空两条本地 BGM，并根据视角进行约 1 秒交叉淡化。
- 语音开始时，BGM 在约 200ms 内压低到当前音量的 30%；语音结束后约 600ms 恢复。
- 已加入以下场景音效：
  - 接近水獭水声
  - 退场水声
  - 回复水纹
  - 行动邀请铃声
  - 普通启声提示
- 同类音效具有 2 秒冷却，避免连续操作产生连响。
- 音效单项加载失败不会中断 BGM、语音或文字聊天。
- elevated 回复保留中性语音并降低 BGM；high/imminent 回复保留安全直述语音，同时关闭 BGM 和装饰音效。
- 页面进入后台时暂停 BGM，恢复可见后平滑继续。
- 卸载时会取消语音、停止媒体、停止音效节点、清除缓存并关闭 `AudioContext`。

### 1.4 声音设置和用户控制

- 顶栏增加“开启声音”按钮，首次必须由用户明确点击解锁浏览器声音权限。
- 点击开启后，语音、BGM 和音效默认启用。
- 设置面板已提供：
  - 声音总开关
  - 语音开关
  - BGM 开关
  - 音效开关
  - 总音量滑块
  - 语音音量滑块
  - BGM 音量滑块
  - 音效音量滑块
- 默认音量为总音量 `0.80`、语音 `1.00`、BGM `0.25`、音效 `0.35`。
- 设置采用带版本号的本地存储，刷新后可恢复；损坏数据会回退到默认值。
- 声音引擎挂载在应用根部，场景切换和对话抽屉开关不会重建音频引擎。

### 1.5 服务端契约和特性开关

- 已新增并接入 `AgentIdV1`、`AudioCueV1`、`AudioSfxV1`、`SoundscapePolicyV1` 等共享类型。
- `ChatTurnResponse` 支持可选 `audioCue`，`RuntimeInfo` 返回 `audioV1Enabled`。
- 已实现确定性的 `buildAudioCue()`，根据 Agent、回应模式、行动邀请和风险等级生成声音指令。
- Demo 和 Full 聊天响应使用同一 `audioCue` 字段结构。
- Full 模式会把完整响应及 `audioCue` 写入现有 `Turn.resultJson`，不需要数据库迁移。
- `AUDIO_V1` 已接入环境配置：Demo 默认开启，Full 默认关闭。
- `SCENE_WORLD_V1` 已接入环境配置：Demo/Lab 默认开启，Full 默认关闭。
- 本地静态服务已补充 MP3 等音频 MIME 类型。

### 1.6 临时素材和许可记录

- 两条 BGM 和四个音效来源已下载到项目本地，不依赖运行时外链。
- 音效已裁剪为产品所需的五种用途，BGM 已控制循环、响度和文件大小。
- 所有声音资源通过固定 ID 注册，支持单项失败降级。
- 已记录素材标题、作者、来源 URL、许可和临时素材标记。
- 当前声音素材来自 Pixabay，仅作为功能开发和内部 Demo 的临时资源。

## 4. 剩余任务

### 4.1 发布前必须完成

1. 在具有有效模型服务和网络的 Full 环境重新执行 `npm run preflight:full`。
   - 当前 Node、配置、端口、PostgreSQL和迁移均通过。
   - 当前唯一失败项是外部模型在线探测返回 `provider_error`。
2. 完成真实设备人工试听。
   - Windows Edge/Chrome
   - macOS Safari
   - iOS Safari
   - Android Chrome
   - 检查系统中文声线、BGM 循环接缝、实际响度、蓝牙切换、中断恢复和后台恢复。
3. 完成真实移动设备场景测试。
   - 至少一台中端 Android 和一台 iPhone。
   - 检查触摸、软键盘、抽屉遮挡、横竖屏和长时运行。
4. 替换或正式确认临时 Pixabay BGM 和音效。
   - 完成商用授权复核、响度统一和正式素材归档。
5. Demo 灰度验收通过后再考虑在 Full 开启 `AUDIO_V1` 和 `SCENE_WORLD_V1`。

### 4.2 场景精修任务

- 获取正式的干净水獭角色分层图或 spritesheet。
- 将当前受控光环、位移和涟漪替换为更完整的角色动作帧。
- 评估并实现动态 `RenderTexture` 倒影；当前继续使用原图中烘焙倒影。
- 主动触发 WebGL context loss，补充恢复和静态回退的专项测试。
- 建立正式截图基线和视觉评审流程。
- 在真实设备上执行至少 30 分钟场景性能与温升测试。

### 4.3 声音后续版本任务

- 接入云端 TTS，并通过替换 `SpeechAdapter` 保持现有页面和 `AudioDirector` 不变。
- 增加语音流式播放、取消、私有缓存和供应商降级策略。
- 为后续新增 Agent 注册独立声线；当前注册表只有 `spirit_otter`。
- 评估正式安全声线、发音词典和多语言能力。
- 如产品需要，再增加暂停/继续、用户自选音色和语速控制。
- 评估语音口型或逐字动画同步；不属于 v1。

### 4.4 工程与发布管理

- 当前变更尚未提交 Git；发布前需要审查改动范围并创建正式提交。
- 更新原声音系统设计文档的“待评审”状态，使其与已经落地的 v1 实现一致。
- 为临时素材替换、外部模型预检和人工设备验收建立发布清单与负责人。
- Full 开启声音后重新执行 build、typecheck、unit、integration、Demo E2E、Full E2E 和声音长时测试。

## 5. 当前不属于 v1 的范围

- 真人声音克隆或正式角色配音。
- 云端 TTS 音频文件持久缓存。
- 流式语音和逐字动画同步。
- 用户自选音色、语速和发音词典编辑器。
- 多语言朗读。
- 完整角色骨骼动画和高成本动态倒影。

## 6. 推荐执行顺序

1. 配置可用的 Full 模型服务，完成在线预检和模型验收。
2. 在 Windows 与移动真机完成场景和声音联合人工验收。
3. 确认或替换正式 BGM、音效和角色分层素材。
4. 修复验收发现的问题，再执行一次完整自动化回归。
5. 先在 Demo 灰度开放声音与动态场景。
6. 观察稳定性和反馈后，再决定是否为 Full 开启两个特性开关。
