# BoonZoom 三圈世界与社区联动设计 v1

日期：2026-08-25

状态：`product-baseline`，社区能力尚未实现

适用角色：鹿禅、tata、飞儿及用户自己的后续 Agent 小队

## 1. 产品空间基线

BoonZoom 的世界由三个权限逐步扩大的圈层组成：

1. **内圈｜私密船上世界**：用户与自己的 Agent 小队所在的个人世界。
2. **中圈｜熟人社交**：用户主动进入的可信关系、小范围兴趣组与受邀活动。
3. **外圈｜公共社区**：面向更广泛人群的公开内容、活动发现与社区连接。

用户停留在船上时，默认处于内圈。中圈和外圈可以在远处形成可见的灯火、来信或活动窗口，但不得主动闯入私人对话。用户可以先查看最小信息，再决定是否跨圈。

## 2. 对旧水世界方案的修正

自本设计生效后，以下旧定义不再作为当前产品规范：

- 不再使用“水下、接近水面、水面”表示情绪或支持阶段。
- 不再使用下潜、上浮、捞起或漂浮物表示用户的心理状态、任务或回访。
- 不要求鹿禅、tata 或飞儿划船，也不以航行进度表达关系或任务进度。
- 不把水面/星空镜头切换、涟漪或水域动画视为产品信息架构。

湖面、小船、星空和远方灯火仍可作为克制的视觉环境；它们只负责空间氛围和圈层距离，不推断用户情绪，不制造进度，不替代清楚的权限文案。

旧水面世界文档保留为历史实现记录，但不能覆盖本文件、产品体验宪法或当前角色规范。

## 3. 内圈｜私密船上世界

### 3.1 成员与可见性

- 默认成员只有用户和用户自己的 Agent 小队。
- 不显示其他真人的在线状态、头像、消息或活动轨迹。
- 每个 Agent 的一对一对话默认彼此隔离；“同属一个小队”不等于自动共享全部对话。
- 用户可主动召集多 Agent 会话。召集前应展示参与角色，以及将共享的摘要或字段。
- Agent 间交接只传递用户确认的最小结构化信息，不传递整段私密对话、未确认推测、疗愈洞察或敏感记忆。

### 3.2 内圈角色分工

| 角色 | 内圈职责 | 不得做的事 |
| --- | --- | --- |
| 鹿禅 | 禅宗观照、传统文化与命理文化解释、清简陪伴 | 用玄学替用户断定现实；把私密内容带到社区 |
| tata | 温馨体贴的日常陪伴、具体照顾感受与余力 | 强化依赖；替用户公开情绪或关系内容 |
| 飞儿 | 生活秘书、兴趣档案、活动信使、圈层入口说明 | 秘密画像；自动推送、报名、联系、发帖或分享 |

角色可以提出“是否交给另一位 Agent”的低压力邀请，但用户拒绝后必须停止；不得为了体现 Agent 小队而频繁串场。

### 3.3 内圈数据

内圈数据包括私密对话、角色记忆、支持偏好、兴趣档案草稿、行动与回访。它们默认不能用于：

- 生成公开个人主页；
- 给其他用户匹配或推荐；
- 在中圈或外圈展示；
- 代替用户发布、报名、联系或加入群组；
- 推断并公开情绪、命理结论、健康状况或关系状态。

用户应能分别查看、纠正、停用、导出和删除各类数据。删除一种档案不得被另一个 Agent 的记忆悄悄恢复。

## 4. 中圈｜熟人社交

中圈是低规模、可识别、可退出的社会连接层，不等同于公开广场。

可包含：

- 用户主动确认的朋友、同伴或熟人；
- 有明确成员范围的小组；
- 受邀请进入的活动房间；
- 用户选择关注的兴趣主题与组织者。

中圈默认规则：

- 加入、邀请他人、发送消息、共享资料和开启通知分别授权。
- 进入前展示成员或受众范围、可见字段、保存期限和退出方式。
- 不默认展示精确位置、私密对话、情绪标签、命理资料或长期兴趣画像。
- 退出后停止新消息和通知；历史内容如何保留必须在进入前说明。
- Agent 可以陪同解释和整理，但不能冒充用户发言，也不能替用户维护社交关系。

## 5. 外圈｜公共社区

外圈承担发现和公开连接，不以提高停留时长或社交压力为目标。

首批适合开放的能力：

- 浏览公开活动和主题内容；
- 查看来源、更新时间、主办方、费用、地点范围与参与条件；
- 收藏、减少此类推荐或屏蔽来源；
- 将公开信息带回内圈，与 Agent 私下讨论。

以下均为独立外部动作，不能打包授权：

1. 报名活动；
2. 联系组织者或其他成员；
3. 加入群组；
4. 发布内容或评论；
5. 共享个人资料、兴趣、位置或联系方式；
6. 开启站外通知。

执行前必须展示即将发送的字段、接收方和可见范围；执行后显示真实结果。失败、待审核和草稿不得冒充成功。

## 6. 三圈之间的移动规则

### 6.1 看见不等于进入

用户留在船上时，可以看到中圈邀请、外圈活动摘要或远方灯火。浏览这些最小信息不应自动创建社交身份、关注关系、兴趣档案或通知订阅。

### 6.2 跨圈必须由用户发起或确认

一次确认只授权一个清楚动作。例如“看看活动详情”不等于“报名”，“加入小组”不等于“公开个人档案”，“交给飞儿看看”不等于允许飞儿长期保存。

### 6.3 返回内圈始终可用

用户可随时回到私人世界。返回内圈不产生离开惩罚、未读压力、连续签到损失或 Agent 失望。中外圈通知必须可分别关闭。

### 6.4 安全路径高于世界沉浸

高风险状态统一进入 `safety_plain`。系统暂停圈层邀请、活动推荐、外部动作和角色表演，提供直接、现实的安全支持。

## 7. 飞儿的社区桥梁职责

飞儿连接的是信息与授权流程，不是把用户画像送往社区。

她可以：

- 把公开活动目录带到内圈；
- 根据用户已确认的兴趣和约束进行本地排序；
- 解释推荐理由、来源和更新时间；
- 在跨圈前整理字段预览并请求单次授权；
- 帮用户降低或关闭推荐频率。

她不可以：

- 从鹿禅或 tata 的私密对话秘密提取社区画像；
- 把情绪、创伤、命理结果、健康或关系内容用于活动匹配；
- 自动替用户维护熟人关系、回复消息或塑造公开人格；
- 因用户不参加活动而催促或制造错过焦虑。

## 8. 当前能力与阶段

当前项目已建立三角色身份与语音边界，但运行界面仍以鹿禅为主要活动角色。下列能力尚未完成：

- tata 与飞儿的独立完整入口；
- 多 Agent 召集与最小字段交接界面；
- 中圈关系和小组模型；
- 外圈社区、真实活动目录与内容治理；
- 报名、联系、加入、发布及撤销流程；
- 多人隐私、未成年人、骚扰、封禁、举报和申诉体系。

未完成前，界面和角色必须明确说明能力缺失，不展示虚构在线用户、活动或执行成功状态。

现有代码中保留的 `underwater_companion`、`near_surface_transition`、`surface_organize` 等名称只属于迁移前的内部兼容状态；在完成实现迁移前不得把它们继续解释为当前产品世界观。

## 9. 分阶段建设

### Phase A｜稳固内圈

- 完成三角色独立入口和一对一会话隔离。
- 完成 Agent 间最小字段交接、授权预览和撤销记录。
- 完成兴趣档案与记忆的分区管理。

### Phase B｜只读外圈与飞儿信箱

- 接入经过审核的只读活动目录。
- 用户留在内圈即可查看活动摘要和推荐理由。
- 不开放报名、联系、发帖、群组或主动通知。
- 首个可执行版本见 `docs/inner-outer-circle-switch-v0.1-plan.md`。

### Phase C｜受控通知与外部动作草稿

- 用户自选通知频率与免打扰时间，默认仍关闭。
- 支持报名、联系和发布草稿，以及发送字段预览。
- 草稿不冒充完成；真实执行继续关闭。

### Phase D｜受控中圈与有限外部动作

- 开放小范围邀请制关系和小组，明确成员、历史保留和退出规则。
- 完成屏蔽、举报、内容治理和多人隐私评审后，再按动作分别开放报名、联系、加入和发布。
- 每次展示字段与受众并取得单次确认。
- 建立失败恢复、撤销、退出、申诉和审计能力。

## 10. 体验不变量与验收

本设计影响：`EX-02`、`EX-03`、`EX-04`、`EX-05`、`EX-07`、`EX-08`、`EX-09`、`EX-10`。

新增社区空间约束：

- `CI-01`：内圈私密内容默认不得跨圈。
- `CI-02`：同一 Agent 小队不等于默认共享全部对话。
- `CI-03`：看见、查看、加入、联系、发布和分享分别授权。
- `CI-04`：用户始终可以无惩罚返回内圈并关闭通知。
- `CI-05`：飞儿只携带必要信息，不携带用户的私密世界。
- `CI-06`：未连接或失败的社区能力必须如实呈现。
- `CI-07`：相关性、活跃度或报名率不得凌驾于隐私、节奏和退出权。
- `CI-08`：高风险状态停止社区推动和沉浸表达。

自动硬门禁至少覆盖：未授权跨圈传输、未授权外部动作、删除后继续使用、虚构社区执行、跨用户泄漏和高风险继续推动。角色自然度、圈层安全感、跨圈压力和退出体验必须保留人工评审，不能用点击率替代。
