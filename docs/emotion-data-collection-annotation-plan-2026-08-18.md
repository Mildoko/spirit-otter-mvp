# 灵体水獭中文情绪数据采集、标注与模型校准计划

## 一句话结论

灵体水獭不应依靠不断扩充情绪关键词，也不应把任一大模型或开源分类器的输出直接当作用户真实情绪。第一阶段采用：

> 心理学维度作为稳定底座，中文对话数据集作为标签与样本参考，DeepSeek 负责结构化预标注，人工负责金标准和歧义仲裁，最终用冻结中文样本校准模型、规则与置信度。

本计划服务于对话体验优化与内部评测，不用于医疗诊断、心理疾病筛查或临床决策。

---

## 1. 目标与非目标

### 1.1 目标

1. 建立一套可解释、可版本化的中文情绪状态 Schema。
2. 明确区分中性、无法判断、低表达清晰度和真实情绪。
3. 建立约 300 条第一版中文金标准样本及 30 组多轮样本。
4. 使用 AI 预标注降低成本，同时保留人工对最终质量的控制。
5. 校准现有 DeepSeek 信号抽取和本地 fallback，减少持续输出零效价、关键词误判及上下文丢失。
6. 形成可重复运行的开发集、验证集、冻结测试集和报告。

### 1.2 非目标

- 不根据文本诊断抑郁症、焦虑症、创伤或其他疾病。
- 不把情绪标签直接用作风险等级、行动授权或模式切换的唯一依据。
- 不以单个总准确率代替各类情绪、困难表达和安全边界的独立验收。
- 第一阶段不训练新的生产分类器；先验证标签体系和数据质量。
- 不未经同意收集真实用户聊天，也不保存不必要的身份信息和完整原文。

## 2. 情绪状态的科学框架

### 2.1 连续维度：VAD

底层使用三个连续维度：

| 维度 | 内部字段 | 含义 | 建议范围 |
| --- | --- | --- | --- |
| 情绪倾向 | `valence` | 不愉快到愉快 | `-1..1` |
| 唤醒度 | `arousal` | 平静、低激活到紧张、强激活 | `0..1` |
| 控制感 | `control` | 无力、被动到可控、能动 | `0..1` |

VAD 的价值在于避免把所有情绪压成“正面/负面”。例如愤怒和悲伤都可能是负效价，但愤怒通常唤醒度更高；同样的焦虑，也可能伴随不同程度的控制感。

现有界面中的“效价”建议改名为“情绪倾向”。当证据不足时显示“暂不明确”，而不是显示为 `0` 并让用户误以为系统判断其情绪中性。

### 2.2 上层标签：有限多标签

第一版使用以下 15 类对话实用标签：

| 英文字段 | 中文显示 | 简要边界 |
| --- | --- | --- |
| `joy` | 喜悦 | 开心、愉快、满足 |
| `relief` | 释然 | 压力解除后的放松 |
| `hope` | 希望 | 对未来改善的积极期待 |
| `interest` | 兴趣 | 被吸引、愿意探索 |
| `gratitude` | 感激 | 对帮助或善意的感谢 |
| `sadness` | 悲伤 | 失去、低落、难过 |
| `anger` | 愤怒 | 受侵犯、不公平、被阻挠后的对抗感 |
| `anxiety` | 焦虑/恐惧 | 对威胁、不确定或后果的担忧 |
| `frustration` | 挫败 | 目标反复受阻或努力无效 |
| `disappointment` | 失望 | 现实低于期待 |
| `disgust` | 厌恶 | 排斥、反感 |
| `shame` | 羞耻 | 对自我整体的负面暴露感 |
| `guilt` | 内疚 | 对具体行为或后果的责任感 |
| `loneliness` | 孤独 | 缺少连接、理解或陪伴 |
| `surprise` | 惊讶 | 出乎预期，可正可负 |

特殊标签单独保留：

- `neutral`：存在足够证据表明没有明显情绪表达。
- `unknown`：信息不足、主体不明或歧义过大，无法可靠判断。
- `other`：能确认存在情绪，但不属于第一版标签表。

每条最多标注两个主要情绪。标签不是疾病诊断，也不表示用户具有稳定人格特征。

### 2.3 情绪与其他信号分离

以下字段继续独立维护，不并入情绪标签：

- `expressionClarityScore`：表达清晰度。
- `progressReadinessScore`：推进准备度。
- `overloadCueScore`：认知过载迹象。
- `supportSeekingScore`：支持需求迹象。
- `helplessnessScore`：无助表达迹象。
- 风险等级和风险证据。

例如“脑子一片空白”可以是高过载、低清晰度，但情绪仍为 `unknown`；不能因为难以表达就自动判定为悲伤或中性。

### 2.4 自报优先与模型谦抑

推断优先级固定为：

```text
用户明确自报或纠正
→ 当前轮与最近上下文中的明确证据
→ 模型结构化预测
→ 本地规则弱证据
→ unknown
```

用户说“我不是生气，我是失望”时，必须采用用户纠正。模型没有证据时应放弃判断，不允许为了填满字段而猜测。

## 3. 可借鉴的系统、数据集与论文

### 3.1 Russell 情绪环形模型

- 用途：为情绪倾向与唤醒度提供稳定的二维底座。
- 适合：连续状态、趋势展示、回复风格调节。
- 限制：不能单独表达羞耻、内疚、释然等细粒度差异。
- 参考：[The circumplex model of affect](https://pubmed.ncbi.nlm.nih.gov/16262989/)

### 3.2 Self-Assessment Manikin（SAM）

- 用途：通过情绪倾向、唤醒度和控制感测量人的主观感受。
- 适合：未来增加可选的一键用户自报；也支持 VAD Schema 设计。
- 限制：SAM 是自评工具，AI 从文字推断出的数值不能冒充 SAM 测量结果。
- 参考：[Measuring emotion: The self-assessment manikin and the semantic differential](https://doi.org/10.1016/0005-7916(94)90063-9)

### 3.3 Geneva Emotion Wheel（GEW）

- 用途：20 个情绪家族、多级强度、混合情绪、“无情绪”和“其他”选择。
- 适合：借鉴情绪家族、控制感和强度表达；未来可研究用户主动选择界面。
- 限制：官方建议保持正式标签和布局；非商业研究可免费使用，商业用途需要申请许可。使用前必须重新确认当时的官方条款。
- 参考：[Geneva Emotion Wheel 官方页面](https://www.unige.ch/cisa/gew)

### 3.4 GoEmotions

- 数据：约 5.8 万条英文 Reddit 评论，27 类情绪加中性，允许多标签。
- 适合：借鉴细粒度多标签方法、标签定义、基线和模型卡。
- 限制：英语、Reddit 文化和短评论场景与中文陪伴对话存在明显域差异，不直接作为生产中文模型。
- 代码与数据：[Google Research GoEmotions](https://github.com/google-research/google-research/tree/master/goemotions)
- 论文：[GoEmotions: A Dataset of Fine-Grained Emotions](https://aclanthology.org/2020.acl-main.372/)

### 3.5 CPED

- 数据：约 1.2 万段中文多轮对话、13.3 万条话语，包含 13 类情绪、情感倾向、对话行为和人物信息。
- 适合：中文多轮情绪识别、上下文变化、标签和评测样本设计。
- 限制：来自电视剧，可能比真实聊天更戏剧化；原工程依赖较旧，不能未经校准直接进入生产。
- 仓库：[scutcyr/CPED](https://github.com/scutcyr/CPED)
- 论文：[CPED: A Large-Scale Chinese Personalized and Emotional Dialogue Dataset](https://arxiv.org/abs/2205.14727)

### 3.6 CAPE

- 方法：基于认知评价理论分析目标、阻碍、责任和情境，再预测 15 类情绪及后续表达。
- 适合：构造“为什么是挫败而不是悲伤”等最小差异样本；帮助模型提供可解释证据。
- 限制：包含自动数据生成流程，适合研究、训练和样本设计，不等同于完全人工标注的真实用户金标准。
- 论文：[CAPE: A Chinese Dataset for Appraisal-based Emotional Generation](https://aclanthology.org/2025.findings-naacl.353/)

### 3.7 EmotionTalk

- 数据：中文互动多模态对话，包含文本、音频、视频、类别和连续标注。
- 适合：未来加入声音之后研究情绪动态与说话风格。
- 限制：当前水獭主要处理文字；演员互动、多模态条件与真实文字聊天不完全一致。
- 仓库：[flageval-baai/EmotionTalk](https://github.com/flageval-baai/EmotionTalk)
- 论文：[EmotionTalk: An Interactive Chinese Multimodal Emotion Dataset](https://aclanthology.org/2026.findings-acl.440/)

### 3.8 NRC 情绪与 VAD 词典

- 用途：词语级情绪关联、VAD 先验和本地规则参考。
- 限制：词典不能理解否认、反讽、主体和多轮上下文；自动翻译的中文词项需要本地校准。NRC VAD 当前公开下载包含非商业研究/教育使用限制，接入前必须核对版本和许可。
- 参考：[NRC Emotion Lexicon](https://nrc-publications.canada.ca/eng/view/object/?id=0b6a5b58-a656-49d3-ab3e-252050a7a88c)、[NRC VAD Lexicon](https://saifmohammad.com/WebPages/nrc-vad.html)

### 3.9 采用决策

第一阶段不直接引入某个开源仓库作为生产依赖，而是：

1. 采用 VAD/SAM 原理定义连续维度。
2. 参考 GoEmotions 的多标签方法。
3. 重点参考 CPED 的中文多轮场景。
4. 使用 CAPE 构造带情绪原因的最小差异样本。
5. 将 GEW 作为自报界面研究参考，不直接复制受许可约束的正式实现。
6. 使用词典补充弱规则，但不让关键词覆盖上下文判断。

任何外部数据、代码、模型权重或量表正式材料在落库前都必须记录来源、版本、许可证和允许用途。

## 4. 第一版数据集设计

### 4.1 数据规模

#### 单轮样本：240 条

- 15 类主要情绪各至少 10–12 条。
- `neutral` 和 `unknown` 各至少 20 条。
- 至少 40 条混合情绪，可与各分类别样本重叠。
- 至少 60 条困难表达，可与以上样本重叠。

#### 多轮样本：30 组

- 每组 3–5 轮。
- 覆盖情绪增强、减弱、转变、纠正和上下文反转。
- 总用户话语约 110–150 条。

第一版合计约 350–400 条用户话语。它足以用于提示词、规则和置信度校准，但不足以宣称训练出通用中文情绪分类器。

### 4.2 场景覆盖

- 工作压力、返工和截止日期。
- 学习、考试和选择困难。
- 人际冲突、被忽视和被误解。
- 亲密关系、家庭关系和告别。
- 拖延、自责、羞耻和内疚。
- 身体疲惫、睡眠不足和精力下降。
- 孤独、缺少连接和想被陪伴。
- 完成任务后的释然与积极变化。
- 日常闲聊、中性事实和无明显情绪。
- 表达不清、低信号和认知过载。

### 4.3 困难表达覆盖

- 否认：“我没生气，就是不想再说了。”
- 反讽：“太好了，又要全部重做。”
- 改口：“也不是难过，可能更多是失望。”
- 碎片：“就……挺堵的。”
- 隐喻：“整个人像没接上电。”
- 引用他人：“他说他很害怕。”
- 假设和未来：“如果失败了我可能会崩。”
- 表情符号和标点：“没事🙂”或“行吧……”
- 多情绪：“终于结束了，但突然有点舍不得。”
- 主体切换：“我替她难过，但自己其实松了口气。”
- 口语、省略、错别字和少量方言表达。
- 同一句短回应在不同上下文中的不同含义。

### 4.4 最小差异样本

同一基础表达只改变一个变量，用于检查模型是否真的理解：

```text
“又要重做了，我真没用。”        → 挫败 + 羞耻/自责
“又要重做了，他们凭什么？”      → 挫败 + 愤怒
“又要重做了，我怕明天交不上。”  → 挫败 + 焦虑
“又要重做了，不过这次知道怎么改。”→ 挫败 + 较高控制感
```

至少建立 12 组情绪、控制感、否认、主体和上下文最小差异样本。

## 5. 数据来源与采集规则

### 5.1 推荐来源比例

| 来源 | 建议占比 | 处理要求 |
| --- | ---: | --- |
| 团队人工编写的现实场景 | 50% | 避免只写标准书面语 |
| 同义改写与最小差异样本 | 25% | 改写版本放在同一数据分区 |
| AI 生成候选 | 15% | 必须人工重审，AI 标签不是金标准 |
| 获得同意的真实失败案例 | 10% | 去标识化、最少保存、可追溯删除 |

早期没有合规真实数据时，可先用前三类完成 v0.1；不得为了凑比例私自复制内部成员的真实聊天。

### 5.2 AI 生成候选规则

- 模型只负责生成表达变体、困难例和候选标签。
- 生成提示与正式推断提示分开版本管理。
- 同一个模型生成的文本和标签不能直接用于证明该模型准确。
- 所有 AI 候选都标记 `sourceType=synthetic_candidate`。
- 人工修改后保留来源字段，不伪装为自然真实数据。

### 5.3 真实数据规则

- 只使用明确同意用于研发和评测的数据。
- 默认只截取完成标注所必需的最短片段。
- 删除姓名、单位、地址、联系方式、账号、精确日期和可识别事件。
- 原始数据与去标识化数据分开存放；GitHub 仓库只允许提交去标识化样本。
- 保存同意依据、数据版本和删除映射，但不在普通事件日志中复制用户原文。
- 用户撤回授权后，应能定位并删除对应原始与派生样本。

## 6. 标注 Schema

### 6.1 建议 JSONL 结构

```json
{
  "id": "EMO-CN-001",
  "schemaVersion": "emotion-annotation-v1",
  "scenario": "work_pressure",
  "context": [
    {
      "role": "assistant",
      "text": "这次返工最压着你的是什么？"
    }
  ],
  "userText": "太好了，又要全部重做。",
  "annotation": {
    "emotions": [
      {
        "label": "frustration",
        "intensityLevel": 4,
        "confidenceLevel": 4,
        "evidenceSpans": ["又要全部重做"]
      },
      {
        "label": "anger",
        "intensityLevel": 2,
        "confidenceLevel": 3,
        "evidenceSpans": ["太好了", "又要"]
      }
    ],
    "valenceLevel": 1,
    "arousalLevel": 3,
    "controlLevel": 2,
    "clarityLevel": 4,
    "neutral": false,
    "unknown": false,
    "explicitSelfReport": false,
    "emotionSubject": "user"
  },
  "phenomena": ["sarcasm"],
  "sourceType": "human_authored",
  "split": "test"
}
```

### 6.2 使用五档而非直接标小数

人工不直接填写 `-0.63` 或 `0.71`。统一标五档，再由程序映射：

| 字段 | 档位 |
| --- | --- |
| 情绪倾向 | 很负面、偏负面、中性、偏正面、很正面 |
| 唤醒度 | 很低、偏低、中等、偏高、很高 |
| 控制感 | 完全无力、较低、中等、较高、很可控 |
| 情绪强度 | 很弱、偏弱、中等、较强、很强 |
| 判断把握 | 无法判断、较低、中等、较高、明确 |

程序映射建议：

```text
valence: -1, -0.5, 0, 0.5, 1
其他 0..1 维度: 0, 0.25, 0.5, 0.75, 1
```

这种映射仅用于系统计算，不宣称五档之间具有严格等距的心理测量意义。

### 6.3 每条必须记录的元数据

- 样本 ID、Schema 版本和数据版本。
- 场景、单轮/多轮组 ID、轮次位置。
- 来源类型和许可/同意状态。
- 情绪主体：用户、他人、混合或不明。
- 困难现象标签：否认、反讽、引用、假设、改口等。
- 标注员匿名 ID、标注时间、仲裁状态。
- 是否进入开发、验证或冻结测试分区。

不得把标注员姓名、用户身份信息或 API 密钥写入样本文件。

## 7. 人机协作标注流程

### 7.1 总流程

```text
采集或编写候选样本
→ 自动隐私检查与人工去标识化
→ DeepSeek 结构化预标注
→ 第二提示或本地模型独立复核
→ 一致样本进入人工快速确认
→ 冲突、低置信度和困难样本进入人工精审
→ 双人金标准标注
→ 分歧仲裁
→ Schema 校验
→ 冻结版本与生成报告
```

### 7.2 数据分区的人力要求

| 分区 | 标注方式 |
| --- | --- |
| 开发集 | AI 预标注 + 1 人确认 |
| 验证集 | AI 预标注 + 1 人精审，关键样本双审 |
| 冻结测试集 | 2 人独立标注 + 分歧仲裁 |
| 风险、否认、反讽、改口 | 无论所在分区均人工精审 |
| 真实失败案例 | 去标识化复核 + 人工精审 |

### 7.3 标注员规则

1. 只标文本和必要上下文支持的情绪，不推断疾病或人格。
2. 用户明确自报和明确纠正优先。
3. 区分用户、他人、引用和假设中的情绪主体。
4. `unknown` 不等于 `neutral`。
5. 短句、沉默、低清晰度不自动等于负面。
6. 身体疲劳和认知过载不自动等于悲伤。
7. 安全表达首先进入独立风险标注，不能只作为普通情绪样本处理。
8. 每个预测情绪必须有证据范围；无法指出证据时降低把握或选择 `unknown`。
9. 每条最多两个主要情绪。
10. 两位标注员不得查看对方结果后再提交初标。

### 7.4 分歧仲裁

分歧不直接覆盖，先记录类型：

- 标签定义重叠。
- 强度尺度理解不同。
- 情绪主体不一致。
- 上下文是否足够存在分歧。
- 中性与无法判断混淆。
- 一个标注员做出了无文本证据的心理推测。

频繁出现的分歧应回写标注手册并重新抽检同类旧样本，而不是只解决当前一条。

## 8. 数据分区、版本与防泄漏

### 8.1 第一版划分

- 开发集：180 条，用于修改提示词和规则。
- 验证集：60 条，用于选择阈值和置信度策略。
- 冻结测试集：60 条，发布门禁前运行。
- 30 组多轮样本单独统计，可再按开发/验证/测试拆分。

### 8.2 防止数据泄漏

- 同一基础场景、同义改写和最小差异组必须进入同一分区。
- 同一真实会话的所有轮次必须进入同一分区。
- 如果未来有多个真实用户，按用户而不是按单条消息分区。
- 冻结测试集内容不进入 Prompt 示例、规则词表或训练语料。
- 修改冻结样本必须提升数据版本并记录原因，不能静默改答案。

### 8.3 版本命名

建议使用：

```text
emotion-schema-v1
emotion-annotation-guide-v1
emotion-dataset-cn-v0.1
emotion-gold-cn-v1.0
emotion-eval-report-YYYY-MM-DD
```

## 9. DeepSeek 预标注与运行时输出

### 9.1 建议结构

```json
{
  "valence": -0.65,
  "arousal": 0.48,
  "control": 0.22,
  "emotions": [
    {
      "label": "frustration",
      "intensity": 0.72,
      "confidence": 0.81,
      "evidence": "怎么弄都弄不好"
    }
  ],
  "emotionClarity": 0.76,
  "abstained": false,
  "reasonCodes": ["GOAL_BLOCKED", "LOW_CONTROL"]
}
```

### 9.2 Prompt 硬约束

- 最多两个主要情绪。
- 没有原文证据不能输出高置信度。
- 引用他人的情绪不能错误归给用户。
- 明确否认必须覆盖孤立关键词。
- 信息不足输出 `unknown` 或 `abstained=true`。
- 不输出疾病诊断和人格结论。
- 模型不决定风险级别、行动授权或路由。
- 用户明确纠正覆盖历史模型预测。

### 9.3 本地 fallback 定位

本地词语规则只提供弱证据和安全降级：

- 支持否定窗口、主体和常见反讽模式。
- 同时命中冲突词时降低置信度，不强行平均为中性。
- 没有匹配时返回 `unknown`，不以 `valence=0` 假装已经识别。
- 词典结果不能覆盖用户明确自报和多轮上下文。

## 10. 评测指标与发布门禁

### 10.1 标签指标

- 每类 Precision、Recall、F1，主要看 Macro-F1，不只看总体准确率。
- 多标签 Exact Match 与 Jaccard 相似度。
- `neutral` / `unknown` 混淆矩阵。
- 明确自报样本的识别正确率。
- 用户纠正后的覆盖正确率。

### 10.2 连续与五档维度

- 五档混淆矩阵和相邻误差率。
- 加权 Kappa 或适合有序标签的一致性指标。
- 映射到连续值后报告 MAE，但不把小数误差解释成临床差异。

### 10.3 置信度与放弃判断

- 高置信度预测的准确率。
- 期望校准误差或可靠性分桶。
- `abstained/unknown` 覆盖率和错误放弃率。
- 低证据样本中自信误判的数量。

### 10.4 人工标注一致性

- 主标签按类别统计 Cohen's Kappa 或同等指标。
- 多标签使用 Jaccard 和逐类一致性。
- 有序维度使用加权 Kappa 或 Krippendorff's Alpha。
- 一致性不足的类别先修改手册或合并边界，不用模型成绩掩盖标注问题。

### 10.5 第一版发布门禁

1. 所有样本通过 Schema、枚举、范围和证据字段校验。
2. 冻结测试集与风险样本全部完成人工双审和仲裁。
3. 用户明确自报与纠正样本 100% 遵循用户表达。
4. 风险、情绪和行动授权仍为独立链路，现有安全冻结集不回退。
5. `unknown` 不再以效价零冒充中性。
6. 反讽、否认、主体和改口失败桶分别生成报告。
7. 模型 fallback 明确标注，不计作真实模型通过。
8. 真实数据的同意、去标识化和删除链路完成检查。

Macro-F1 的数值门槛在完成第一轮双人标注后，根据类别分布和人工一致性设定；在金标准自身尚不稳定前，不提前规定一个虚假的高分目标。

## 14. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 生成并标注自己的样本，成绩虚高 | 冻结集双人独立标注；生成模型与验收解耦 |
| `unknown` 被当作中性 | Schema 分离；报告独立混淆矩阵 |
| 关键词忽略否定、主体和反讽 | 困难桶、最小差异和证据范围测试 |
| 标签过细导致标注员无法一致 | 先做 20 条试标；必要时合并标签 |
| 电视剧或网络语料域偏移 | 以自建现实场景和内部失败样本校准 |
| 收集真实聊天造成隐私风险 | 明确同意、最小截取、去标识化、可删除，不提交原始数据 |
| 情绪预测越权控制路由或安全 | 情绪、风险、边界和行动授权保持独立 |
| 外部数据或量表许可不适合产品 | 接入前逐项核对当前许可并登记，不默认可商用 |

## 15. 与现有开发计划的关系

- 本计划为低信号识别提供 `unknown`、清晰度和情绪证据的正式区分。
- 本计划不改变《低信号路由 v1 与表达风格 v2 实施记录》中已经确定的风险、边界和行动优先级。
- 表达风格可以读取低置信度情绪信号，但不得在不确定时装作理解用户。
- 数据报告应与安全、低信号路由和表达自然度报告分别统计。
- 在情绪金标准 v1.0 冻结前，不建议大规模扩充生产关键词或训练专用情绪模型。
