# Core Dialogue bad-case 修复体验评审

## 变更信息

- 变更名称：C01–C29 连续会话 bad-case 修复
- 基线版本 / 候选版本：`policy-2026-08-18.1` / `policy-2026-08-21.1`
- 受影响不变量：`EX-01`、`EX-03`、`EX-04`、`EX-05`、`EX-07`、`EX-08`、`EX-09`
- 受影响路径：承接 / 行动 / 安全 / 角色 / 现实边界
- 预期改善：不提问偏好不再锁死后续意图；风险、依赖、能力边界可确定性生效；行动授权与正文一致；降低机械化表达。
- 可能伤害的体验：安全确认可能突破普通不提问偏好；硬校验过宽可能误伤自然表达；语言收紧可能让回复变得平直。
- 关联 Eval 指标：安全中断、行动结构、依赖边界、能力诚实；自然度与诚恳度仍为人工评审。

## 决策

- [ ] 接受：核心体验未退化，证据充分
- [ ] 调整实现：指标或功能改善，但体验存在退化
- [ ] 调整 Eval：候选体验更好，但指标或 Judge 偏离产品目标
- [x] 继续人工验证：自动修复完成后需要模型结果与用户复测

- 决策理由：安全与结构修复可以自动验证，语言自然度、诚恳度和角色连续性不能自动宣称通过。
- 测量迁移说明：根据本轮明确用户反馈，非冻结的情绪表达单元测试从要求“停留空间”改为要求回应“具体的失去或难过”；未修改开发校准集、冻结安全语料、阈值或 Judge。
- 真实模型状态：DeepSeek 通道已实际运行；安全硬门禁为零失败，但 4 个 elevated 轮次在单次修复后仍超过问题预算，因此整次运行按规则标记为 `invalid`，没有用 fallback 冒充模型基线。
- 后续动作：针对 elevated 生成单独做设计评审，决定采用更强的受限生成结构或确定性安全响应；不得通过放宽问题预算或忽略 fallback 使报告通过。随后对至少 24 组回复做盲评。数据库集成测试需在单独提供 `TEST_DATABASE_URL` 后重跑；本轮未新增数据库迁移。
