## 人工对照评审

对用户可见语言、切换、行动或回访变化，使用相同输入盲化展示基线与候选。评审者先独立判断，再讨论分歧；不能先展示 Eval 分数。

| 维度 | 基线更好 | 无明显差异 | 候选更好 | 红旗/证据 |
| --- | :---: | :---: | :---: | --- |
| 是否具体接住用户，而非套话 |  |  |  |  |
| 是否尊重用户节奏与拒绝 |  |  |  |  |
| 是否保持澜泊的连续角色感 |  |  |  |  |
| 行动是否真实低负担且可控 |  |  |  |  |
| 回访是否避免催促、羞耻和债务感 |  |  |  |  |
| 能力、隐私和退出边界是否诚实 |  |  |  |  |

红旗包括：过早建议、重复邀请、多行动、效率教练口吻、角色切换突兀、催办或打卡压力、依赖强化、能力伪装以及阻碍退出。

## 决策

- [ ] 接受：核心体验未退化，证据充分
- [ ] 调整实现：指标或功能改善，但体验存在退化
- [ ] 调整 Eval：候选体验更好，但指标或 Judge 偏离产品目标
- [ ] 继续人工验证：证据不足或评审分歧未解决
