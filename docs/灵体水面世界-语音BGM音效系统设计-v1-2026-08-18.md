# 灵体水面世界：语音、BGM 与音效系统设计 v1

> **历史设计记录。** 水面/星空 BGM 与水域音效不再承担产品状态或圈层含义；后续声音设计按鹿禅、tata、飞儿独立声线及三圈权限重新评审。当前空间方案见 `docs/three-circle-world-and-community-linkage-v1.md`。

日期：2026-08-18  
状态：待评审  
范围：水獭“澜泊”及后续所有 Agent 的语音输出、场景 BGM、交互音效

## 1. 结论

功能可行，建议把声音做成独立于场景渲染的全局 `AudioDirector`，并在服务端建立统一的 Agent 声线注册表和 TTS 适配层。

当前“深潮 / 拾岸”是澜泊的两种回应模式，不应配置成两个完全不同的人声：两者使用同一音色，仅调整语速、停顿与能量。未来新增的公开 Agent 则注册自己的声线，无须修改聊天页面和音频引擎。

首版建议交付：

- 每条新产生的 Agent 回复都可播放语音；文字始终立即展示，不等待语音。
- 2 条无缝循环 BGM：水面视角、星空视角。
- 5～7 个短音效，严格由已定义的场景动作触发。
- 语音播放时自动压低 BGM；安全回应时停止娱乐性音效并将 BGM 淡出。
- 总开关、语音/BGM/音效分项开关与音量设置。
- 用特性开关灰度发布；TTS 失败时不影响文字聊天和安全提示。

浏览器通常会阻止网页在用户尚未交互时自动播放有声内容。因此，“进入页面立即响起 BGM”不能作为可靠行为。首次点击“开启声音”、点击水獭或发送消息时，应完成音频解锁，之后才自动播放语音和 BGM。

## 2. 产品行为定义

### 2.1 “每次发言带语音”的边界

- 仅自动播放本次会话中新产生的 Agent 回复。
- 刷新或重新进入页面时，不自动朗读历史消息。
- 文字回复先展示；语音生成慢或失败时，用户仍可立即阅读。
- 用户可暂停、继续、重播最近一条回复。
- 用户发送下一条消息时，正在播放的上一条回复在 150～250ms 内淡出并取消。
- 连续产生多条 Agent 回复时按生成顺序播放，队列上限建议为 2；超过上限丢弃最旧的未播放项。
- 切换水面/星空视角不打断语音，只切换 BGM。
- 关闭对话抽屉不必停止语音；总静音或语音关闭会立即停止。

### 2.2 澜泊两种模式的声音表现

| 模式 | 音色 | 语速 | 停顿 | 能量与情绪 |
|---|---|---:|---|---|
| 深潮 `deep_tide` | 澜泊统一音色 | 约 0.90～0.94 | 略长 | 安静、容纳、不表演悲伤 |
| 拾岸 `shore_pick` | 澜泊统一音色 | 约 0.98～1.02 | 清晰 | 温和但更有行动感 |
| 安全直述 `safety_plain` | 同一声音或单独的中性安全声线 | 约 0.95～1.00 | 短而清楚 | 中性、直接、无角色化表演 |

这些数值只作为声线试音的起点，最终按所选 TTS 服务和真实设备调校。

### 2.3 所有 Agent 生效

“所有 Agent 生效”通过注册机制实现，不在页面中写死澜泊：

```ts
interface AgentVoiceProfileV1 {
  agentId: string;
  locale: "zh-CN";
  providerVoiceId: string;
  baseRate: number;
  modes: Record<string, {
    rate: number;
    style?: string;
    pauseScale?: number;
  }>;
  safetyVoiceProfileId?: string;
}
```

- 每个可对用户发言的 Agent 必须有一条注册记录。
- 新增 Agent 时，类型检查和测试必须验证其声线已注册。
- 未知 Agent 不静默失败：回退到产品定义的中性声线，并上报日志。
- 模型不能直接指定供应商声线 ID、任意 SSML 或音频地址；这些由服务端确定性规则生成。

## 3. 总体架构

```text
聊天编排器
  ├─ 文字回复
  ├─ agentId / 回应模式 / 风险等级
  └─ 确定性 AudioDirectiveV1
           │
           ├─ TTS API ── VoiceProfileRegistry ── TtsProvider
           │
浏览器 AudioDirector
  ├─ SpeechBus ─────────────┐
  ├─ BgmBus ────────────────┼─ MasterBus ── 扬声器
  └─ SfxBus ────────────────┘
           │
           └─ 音量、静音、压低 BGM、队列、取消、错误恢复
```

音频引擎不放进 Pixi 场景组件中。这样聊天抽屉、场景切换和未来其他页面都可复用同一套声音状态，也避免场景重新挂载导致声音重启。

### 3.1 前端 AudioDirector

建议新增全局 `AudioProvider` / `AudioDirector`：

```ts
type AudioSettingsV1 = {
  masterEnabled: boolean;
  voiceEnabled: boolean;
  bgmEnabled: boolean;
  sfxEnabled: boolean;
  masterVolume: number;
  voiceVolume: number;
  bgmVolume: number;
  sfxVolume: number;
};
```

职责：

- 只创建一个 `AudioContext`，在首次用户操作中创建或恢复。
- 建立 `speechGain`、`bgmGain`、`sfxGain` 和 `masterGain` 四级节点。
- 管理语音播放队列、取消控制器和临时音频 URL 的释放。
- 播放语音时将 BGM 压低约 10～14dB，200ms 淡入压低、600ms 恢复。
- 管理 BGM 无缝循环及 800～1500ms 交叉淡化。
- 将用户设置保存到 `localStorage`；默认是否开启应由产品灰度策略决定。
- 页面进入后台时暂停或降低 BGM；回到前台时平滑恢复。
- 提供统一事件：`unlock`、`speak`、`cancelSpeech`、`setScene`、`playSfx`、`mute`。

长 BGM 建议使用 `HTMLAudioElement`，再通过 `createMediaElementSource()` 接入混音节点；短音效适合预解码为 `AudioBuffer`。这样不会一次性把长音乐全部解码到内存，又能对三类声音统一控制音量。

### 3.2 服务端音频指令

建议在当前聊天响应中增加：

```ts
interface AudioDirectiveV1 {
  schemaVersion: 1;
  agentId: string;
  speech: {
    enabled: boolean;
    voiceProfileId: string;
    prosody: "companion" | "organize" | "safety";
    turnId: string;
  };
  bgm: {
    scene: "horizon" | "sky" | "silent";
    transitionMs: number;
  };
  sfx: AudioSfxV1[];
}

type AudioSfxV1 =
  | "notice_soft"
  | "approach_water"
  | "reply_ripple"
  | "invite_chime"
  | "withdraw_water";
```

指令由服务端根据 `agentId`、回应模式、风险等级和场景状态生成，不能由大模型任意产出。

### 3.3 TTS 接口

建议采用按回复读取的接口：

```text
GET /api/audio/turns/:turnId/speech
```

服务端流程：

1. 校验当前会话是否拥有该 `turnId`。
2. 从服务端保存的回复读取文字，拒绝客户端提交任意待朗读文本。
3. 根据 Agent 注册表、回应模式及安全等级选择声线参数。
4. 调用可替换的 `TtsProvider`。
5. 以流或音频响应返回，并设置 `Cache-Control: private, no-store`。
6. 对相同 `turnId` 做幂等、限流和短时内存缓存，避免重复计费。

```ts
interface TtsProvider {
  synthesize(input: {
    text: string;
    voiceId: string;
    locale: string;
    rate: number;
    style?: string;
    requestId: string;
    signal: AbortSignal;
  }): Promise<AudioStream>;
}
```

只有用户开启语音时前端才请求 TTS，以控制成本。首版可以在文字回复完成后开始拉取音频；后续若延迟不理想，再升级为流式 TTS。浏览器自带 `speechSynthesis` 的声音在不同操作系统上差异过大，不建议作为正式产品方案，可只在本地实验模式中作为降级能力。

## 4. BGM 设计

### 4.1 曲目

首版只做两条低密度无缝循环，避免音乐喧宾夺主：

- `bgm_horizon`：水面视角；缓慢水纹、远处空气感、少量温暖泛音。
- `bgm_sky`：星空视角；更轻、更开阔，可增加极弱的星尘质感。

建议每条 60～120 秒，循环点经过听感检查；切换视角时交叉淡化，发消息时不重新起曲。

### 4.2 混音规则

初始相对增益可从以下范围试音：

- 语音：`1.00`
- BGM：`0.20～0.28`
- 音效：`0.30～0.45`
- 语音播放期间 BGM：降到 `0.07～0.10`

具体值必须使用手机外放、耳机和电脑音箱共同试听后确定。所有增益变化使用短淡化，避免爆音和硬切。

### 4.3 安全场景

- `elevated`：停止邀请类音效，BGM 明显压低。
- `high / imminent`：BGM 在 150～300ms 内淡出，所有装饰性音效关闭。
- 安全回复文字立即出现；语音仅在用户已开启语音时播放，且采用中性直述方式。
- 不使用哭腔、喘息、亲密耳语、双耳刺激或制造依赖感的声音表演。

## 5. 音效设计

音效只响应已有的确定性场景动作，不按字、词或 token 连续发声：

| 场景动作 | 音效 | 规则 |
|---|---|---|
| `idle` | 无 | 保持安静 |
| `notice` | `notice_soft` | 一次轻提示，不使用尖锐铃声 |
| `approach` | `approach_water` | 一次柔和水声 |
| `listen` | 无 | 不干扰用户输入 |
| `think` | `reply_ripple` | 最多一次，不做循环等待声 |
| `speak` | 可无或一次极轻起声 | 不做逐字音效 |
| `invite` | `invite_chime` | 仅低风险场景触发 |
| `withdraw` | `withdraw_water` | 一次淡出水迹 |
| `safety_still` | 无 | 所有装饰音关闭 |

同一音效应设置 2～3 秒冷却，快速状态切换时不重复轰炸。短音效采用固定大小的预加载池，避免无限创建和累计内存。

## 6. UI 与无障碍

- 顶栏增加一个声音按钮，明确显示：未解锁、开启、静音、错误四种状态。
- 首次操作可显示“开启声音”，用户点击后恢复 `AudioContext` 并启动当前场景 BGM。
- 设置面板提供总开关，以及语音、BGM、音效的独立开关和音量。
- 回复旁提供“重播语音”；播放中显示暂停/停止状态。
- 文字回复始终保留，继续作为字幕和无障碍内容；语音不能成为获取信息的唯一途径。
- 提供“安静模式”：保留语音、关闭 BGM 和音效，适合公共环境。
- 自动播放失败时展示一次非阻塞提示，不反复弹窗。

## 7. 隐私、成本与可靠性

- TTS 文字可能包含用户敏感内容的复述；若 TTS 供应商与现有模型供应商不同，需要在隐私说明中明确第三方处理范围。
- 默认不持久化生成的语音：服务端仅做很短的内存缓存，浏览器播放结束后释放临时 URL。
- TTS 响应不放入公共 CDN 或 Service Worker 缓存。
- 为单会话、单用户设置频率和字数上限，避免重复播放造成费用失控。
- TTS 超时或失败时，文字回复正常完成，并提供一次重试；安全支持流程绝不能依赖语音成功。
- 供应商凭证只放在服务端，前端不接触密钥或真实声线 ID。
- 不使用未经授权的真人声音克隆；每个 Agent 声线需有明确的商用范围和授权记录。

## 8. 缺少的声音素材与产品决定

### 8.1 必备素材

1. 澜泊声线试音与最终授权文件；包含深潮、拾岸、安全直述三组样句。
2. 后续每个公开 Agent 的声线定义和授权记录。
3. 发音词典：至少覆盖“澜泊”“浮屿”、角色名、场景名及容易读错的专有词。
4. 2 条 BGM 的 48kHz 高质量母带、无缝循环点、压缩发布版本及版权证明。
5. 5～7 个短音效的母带、发布版本及版权证明。
6. 声音按钮的开启、静音、加载、错误状态图标；也可先使用现有图标库。
7. 隐私说明、TTS 服务保留策略和商用条款确认。

### 8.2 素材格式建议

- 保存 48kHz / 24-bit WAV 母带，用于后续重新编码和调音。
- Web 发布至少准备一种广泛兼容的压缩格式；如需跨浏览器稳健性，可为 `<audio>` 提供多个来源。
- 每条 BGM 保存循环起止点元数据；音效前后裁去无意义空白，并保留极短淡入淡出避免点击声。

### 8.3 尚需确认的产品决定

- 澜泊使用合成角色音，还是经过授权的真人基础音色。
- 安全直述继续使用澜泊音色，还是切到独立中性声线。
- 首次进入默认静音，还是显示一次明确的“开启声音”引导。
- 语音生成成本预算、最大回复朗读字数以及超长回复的分段规则。
- BGM 和音效由内部原创、外包定制还是购买素材库授权。

## 9. 实施阶段与工作量

### 阶段 0：技术与素材定标（1～2 个开发日，素材并行 3～7 日）

- 选择并试跑 TTS 服务；测试中文自然度、首包延迟、取消行为和商用条款。
- 完成澜泊三种模式的试音。
- 确认 BGM、音效制作清单和命名规范。
- 增加 `AUDIO_V1`、`TTS_V1` 特性开关。

### 阶段 1：前端音频引擎（2～3 个开发日）

- 建立 AudioDirector、四路混音、浏览器音频解锁和本地设置。
- 接入两条占位 BGM，完成循环、交叉淡化、后台暂停。
- 建立音效池和确定性动作映射。

### 阶段 2：统一 TTS 服务（3～4 个开发日）

- 建立 `VoiceProfileRegistry` 和 `TtsProvider` 接口。
- 增加 `AudioDirectiveV1` 和按 `turnId` 获取语音的接口。
- 完成权限、取消、幂等、限流、短缓存和错误降级。
- Demo/Lab 模式提供不调用外部供应商的模拟实现。

### 阶段 3：聊天、场景与安全联调（约 2 个开发日）

- 每条新 Agent 回复触发一次语音；接入取消、队列和重播。
- 接入水面/星空 BGM 和场景动作音效。
- 完成 elevated/high/imminent 的静音规则。
- 验证新增 Agent 仅通过注册即可获得声音能力。

### 阶段 4：测试、性能与灰度（2～3 个开发日）

- 自动化测试和多设备人工试听。
- 调整混音、延迟、资源预加载与内存释放。
- 先在 Demo/Lab 开启，内部通过后再在 Full 模式小流量灰度。

完整首版预计 10～14 个开发日，声音素材制作可并行。若首版缩减为一个声线、两条 BGM、五个音效，并先使用非流式 TTS，可压缩到约 7～9 个开发日，不包含外部素材制作与审批时间。

## 10. 自测与验收方案

### 10.1 单元测试

- 所有公开 Agent 都存在声线注册记录；未知 Agent 正确回退并记录错误。
- 深潮、拾岸、安全模式映射到正确的语速和表现参数。
- 风险等级正确覆盖 BGM 和音效指令。
- 语音队列、取消、重播、音量渐变和 BGM ducking 行为正确。
- 本地声音设置可保存、恢复和版本迁移。

### 10.2 服务端集成测试

- 只能读取当前会话拥有的 `turnId`，不能朗读任意客户端文字。
- 返回正确 `Content-Type` 和 `Cache-Control: private, no-store`。
- 同一回复的重复请求具有幂等性并受限流保护。
- TTS 超时、供应商失败和用户取消都能释放连接与资源。
- 不同 Agent 使用自己的注册声线；安全回复使用安全规则。

### 10.3 浏览器端到端测试

- 未交互时不会因自动播放失败产生未处理异常。
- 首次点击声音按钮后 BGM 启动，每条新回复只请求并播放一次语音。
- 刷新后历史回复不自动朗读。
- 发送下一条消息会淡出并取消上一条语音。
- 总静音和关闭语音后不再请求 TTS；单独关闭 BGM/SFX 不影响语音。
- 水面/星空切换时 BGM 交叉淡化，语音不中断。
- 安全场景没有邀请铃声或装饰音，BGM 按规则淡出。

### 10.4 人工设备测试

- 桌面 Chrome、Edge、Safari，以及 iOS Safari、Android Chrome。
- 手机外放、有线耳机、蓝牙耳机；测试来电、耳机断开和音频焦点变化。
- 慢网、断网、TTS 超时、快速连续发送、切换后台再返回。
- 连续使用 30 分钟，确认只有一个 AudioContext，内存和音频节点数量不持续增长。
- BGM 循环无明显接缝，切曲和静音无爆音，语音始终清楚高于背景声。

### 10.5 首版验收门槛

- 新 Agent 回复语音触发成功率不低于 99%（排除主动静音与网络断开）。
- 声音开启后，语音首包目标为文字出现后 P95 小于 1.5 秒；最终阈值以供应商技术验证结果为准。
- 任意时刻最多一个语音实例播放，最多一个 AudioContext 存活。
- TTS 失败不影响文字回复、视觉反馈和安全支持入口。
- 通过全部高风险场景用例，确认无娱乐性 BGM/音效残留。
